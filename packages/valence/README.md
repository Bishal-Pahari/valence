# valence

The Flutter host runtime for [Valence](https://getvalence.pages.dev): your web app runs inside a native
app as a **signed over-the-air bundle**, on top of an **offline-first SQLite** store with incremental sync
and a **typed bridge**. UI changes ship without an app-store review; the native shell is reviewed rarely.

This package is the whole host. You get the loopback server with its per-launch nonce, the canonical
manifest check order, the activation state machine with automatic rollback, the SQLite store and its seed
import, sync with its lease, the strict bridge decoding, and the WebView with its navigation lock, back
gesture and console capture.

Your app supplies two things: its generated config, and its own native bridge methods.

## Setup

```bash
flutter pub add valence
npx valence codegen
```

```dart
import 'package:flutter/material.dart';
import 'package:valence/valence.dart';

import 'valence/bridge.g.dart';
import 'valence/config.g.dart';

Future<void> main() async {
  final valence = await Valence.open(valenceConfig);
  final handlers = AppHandlers(valence);
  runApp(
    MaterialApp(
      home: ValenceApp(
        valence: valence,
        dispatch: (raw, nonce) => bridgeDispatch(handlers, raw, nonce: nonce),
      ),
    ),
  );
}
```

`valenceConfig`, `bridgeDispatch` and `ValenceBuiltins` are generated by `valence codegen` from your
`valence/valence.config.json` and `valence/bridge.schema.json`. Your own methods go in one class:

```dart
class AppHandlers extends ValenceBuiltins implements BridgeHandlers {
  AppHandlers(super.valence);

  @override
  Future<void> hapticsTap() async => HapticFeedback.lightImpact();
}
```

`ValenceBuiltins` already implements `app.*`, `data.*`, `prefs.*`, `sync.*`, `secure.*`, `auth.*`,
`open.external` and `bundle.*` by delegating to the runtime, so only what is app-specific is left
abstract.

## What you still do yourself

The package cannot write native project files, so these are yours:

| | |
|---|---|
| **Assets** | Declare `assets/valence/builtin/`, `assets/valence/builtin/files/` and `assets/valence/seed.db` in `pubspec.yaml`. Flutter asset directories are **not** recursive, so the two `builtin` lines are both needed. |
| **Android `minSdk`** | 23 or later. `flutter_secure_storage`, which holds the bearer token and `secure.*` (contracts §4.4), needs the Keystore APIs added there. |
| **Android cleartext** | `res/xml/network_security_config.xml` permitting cleartext for `127.0.0.1` **only**, referenced from `AndroidManifest.xml`. |
| **Android backups** | `dataExtractionRules` and `fullBackupContent` excluding `valence/`. A restore should start clean from the built-in bundle. |
| **iOS ATS** | The App Transport Security loopback exception. Never `NSAllowsArbitraryLoads`. |
| **iOS backups** | `NSURLIsExcludedFromBackupKey` on the `valence/` directory, from `AppDelegate`. The SQLite file lives *outside* it and is backed up, because it holds user data. |
| **Background sync** | `Valence.backgroundSync(valenceConfig)` is the callable; registering it with `workmanager` or `BGTaskScheduler` is yours. The package deliberately does not depend on `workmanager`, which applies the Kotlin Gradle Plugin and warns on every Android build. |
| **Native value** | At least two of the capabilities in contracts §6, or Apple rejects the app as a repackaged website (guideline 4.2). |

## Things that cost someone a day

- **`PRAGMA journal_mode = WAL` must go through `rawQuery`, not `execute`.** The package does this.
  `sqflite_common_ffi`, the factory `flutter test` uses, accepts `execute`, so no unit test catches it and
  the app dies on its first launch on a phone. Check `store.isWal` in your logs.
- **Never close the database.** sqflite keys open databases by path *inside the platform plugin*, so a
  `close()` in a background isolate invalidates the handle the UI isolate holds. There is deliberately no
  `close` on `ValenceStore`. A background isolate needs `DartPluginRegistrant.ensureInitialized()` first.
- **Build the web app with an absolute base** (`base: '/'` in Vite). The SPA fallback serves the entry page
  at any depth, so a relative asset URL 404s on every nested route — a blank screen with nothing in the
  log, visible only after a reload or a back gesture. `valence bundle` warns about it.
- **The bridge is not a path for bytes.** Messages are capped at 256 KB of UTF-8 each way. Native bytes
  reach the page through `valence.publishHostFile(...)`, which serves them under the reserved `/_host/`
  prefix with `nosniff` and a locked-down CSP.
- **`app.ready()` is what commits an OTA release.** A bundle that never calls it fails its trial twice and
  is rolled back. Call it after the first meaningful paint.

## Rollback

An OTA bundle gets one trial. If `app.ready()` does not arrive within 15 s of foreground time, or the
process dies first, that is a strike; two strikes and the seq goes into `bad` for that install, for ever,
and the previous bundle is served again. Nothing you have to wire up.

To undo a bad release, **roll forward**: re-release the last good web commit, which gets a new, higher
seq. Pointing the channel at an older seq only cancels pending downloads.

## Testing

`flutter test` in this package runs the contracts §8 matrix: every canonical check rejecting, the state
machine's strikes and promotions, the server's three branches in order, the store, sync and the lease.

A green unit suite is **not** evidence the store opens on a phone — see the first gotcha above. The §8
integration row is what covers that.

The bridge IDL and the manifest `format` are additive only. This package's version is independent of your
schema's `BRIDGE_VERSION`.

## Native HTTP (contracts section 4.5)

Generated `http.request` delegates to `Valence.httpRequest`. Configure exact trusted `http.origins` origins, regenerate, and ship a host; they become `ValenceConfig.httpOrigins` (default deny all). The host reads the R1 token per request, with `authToken` callback precedence, and emits `auth.expired` for an authenticated 401. Redirects are returned without following them. Text bodies: 64 KiB; headers: 16 KiB; total deadline: 20 seconds. Use HTTPS in production and no shared server secrets in an APK. [API and adapter guide](https://getvalence.pages.dev/docs/guides/your-backend/). iOS remains experimental and untested.
## Batch reads and sync observations

`Valence.dataGetMany(bucket, keys)` returns distinct live rows in requested order (maximum 500 input keys), using the active manifest schema. `Valence.syncStatus()` reads current outbox depth, last successful unscoped sync time and the last attempt's transport failure. It does not probe connectivity. Generated schema-3 built-ins expose these as `data.getMany` and `sync.status`; `ValenceSyncResult.pending` counts remaining operations. The runtime constrains `path_provider_android` to >=2.2.17 <2.3.0 temporarily for pre-JNI compatibility (U-7, checked 2026-10-21); no app override is needed.

Sync correctness: pull cursors advance only through returned rows, never push echoes or a later server-head max. Fresh pairs satisfy OTA activation only after all pages or static chunks complete. Progress resumes after an interruption. Pending publication retains the data lease; GC protects in-flight manifests and retries stale snapshots. Step 7 waits up to five seconds for ordinary sync. Outbox operations use a durable insertion ordinal; database version 2 migrates legacy queued ids, values and deletes without changing bucket cursors or user rows.


## Local reminders

Schema 5 adds built-in local reminders: notify.schedule/cancel/pending/channels.set, notify.permission, consuming notify.initial, notify.tapped/notify.action and best-effort badge.set/clear. Opt in with notifications.enabled, regenerate, install native receivers/icon/desugaring and ship a store build. Exact requests report downgrades honestly; one-shot epoch times need no device timezone lookup. Images are bounded PNG/JPEG bytes; every action opens the UI. iOS is experimental and untested. See [setup and adoption](https://getvalence.pages.dev/docs/guides/local-notifications/).
