# valence_example

The existing `haptics.tap` now comes from the local `plugins/haptics` Dart package,
with its own schema fragment, matching npm types and setup notes. `main.dart`
registers it in the generated `ValenceBuiltins`; it contains no haptic handler.
The wire shape and schema version stay unchanged. The built-in `open.external`
also uses the plugin API and keeps the runtime's scheme allowlist.

A whole Valence host, to show how little of one you write.

Everything the spec calls the host — the loopback server with its per-launch nonce, the canonical manifest
check order, the activation state machine with its rollback, the SQLite store and its seed import, sync
with its lease, the bridge trust boundary, the WebView with its navigation lock and back gesture — is in
the [`valence`](https://pub.dev/packages/valence) package. This app is the part that is genuinely an app's:

| File | What it is |
|---|---|
| [`lib/main.dart`](lib/main.dart) | The host. About twenty lines: open the runtime with the generated config, and put `ValenceApp` at the root. |
| `AppHandlers` in the same file | Registers the local haptics plugin; all method adapters are inherited from the generated `ValenceBuiltins`. |
| [`valence/bridge.schema.json`](valence/bridge.schema.json) | The app's bridge IDL. Config `plugins` merges the separate haptics fragment into it. |
| [`plugins/haptics`](plugins/haptics/) | A Dart handler package, schema fragment, matching npm types and native setup notes. |
| [`valence/valence.config.json`](valence/valence.config.json) | App id, keyring, OTA and sync bases, the `plants` read-only bucket and the `shelf` writable one. |
| [`lib/valence/*.g.dart`](lib/valence/) | Generated by `valence codegen`. Never edited. |
| `android/`, `ios/` | The platform setup a Dart package cannot write: the Android cleartext config for `127.0.0.1` **only**, the backup rules excluding `valence/`, the iOS ATS loopback exception and the backup exclusion in `AppDelegate`. |
| [`pubspec.yaml`](pubspec.yaml) | The `valence` dependency, and the three asset lines — Flutter asset directories are **not** recursive, so both `builtin` lines are needed. |

## Run it

```sh
flutter pub get
flutter test              # the wiring tests
flutter build apk --debug
```

The OTA and sync hosts in the config are `.invalid`, so nothing leaves the machine: the app serves its
built-in bundle and reads the seeded `plants` bucket offline.

## What the tests prove

[`test/example_test.dart`](test/example_test.dart) covers the half the package's own suite cannot: that
the generated delegations really reach the runtime (a `data.put` that lands in SQLite and comes back from
`data.list`), that this app's own method reaches the dispatcher, and that the policies the package owns —
a read-only bucket, a reserved `prefs` key, a `javascript:` URL — are enforced through the generated path.

The contracts §8 matrix is the package's suite, one directory up. An app does not re-test it.

## Not a device test

The R12 tooling check on 2026-10-21 separately ran this example on Android: seeded batch reads,
two queued writes and a queued delete showed the same pending count in the page and SQLite.
See [the validation record](../../../docs/r12-validation.md). The pre-JNI dependency range resolved
`path_provider_android` 2.2.23. Its prior local override is removed; the runtime carries the constraint.

A green `flutter test` is **not** evidence that the store opens on a phone: it runs on
`sqflite_common_ffi`, which accepts pragmas that Android's `SQLiteDatabase` rejects. Android is the tested
platform for Valence; **iOS is experimental and untested**.

## Native HTTP demo

The schema is now 6 and `http.origins` compiles `http://10.0.2.2:8787` for emulator tests. Run the reference adapter in `examples/rest-sync-adapter/`, set its `ADAPTER_TOKEN` through the Login form, and tap `http.request`. `GET /rpc` returns authenticated status without echoing the token; the other button proves an unlisted origin is denied. No CORS headers are needed. This local HTTP endpoint is for tests; production uses HTTPS. The offline bundle and seed still work without that server.
